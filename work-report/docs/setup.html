업무보고서 설치 안내

앱을 쓰려면 서비스 세 곳을 차례로 연결해야 합니다. 데이터를 담을 Supabase, 보고서를 저장할 구글 드라이브, 앱을 띄울 Vercel입니다. 아래 순서대로 따라가시면 됩니다. 한 걸음씩 마칠 때마다 체크해 두면 어디까지 했는지 남습니다.

1단계

Supabase 프로젝트 만들기

약 10분

업무 데이터가 저장될 곳입니다. 모닝브리프와는 따로 새 프로젝트를 만듭니다. 무료 요금제로 충분합니다.

  1. Supabase에 로그인합니다

    supabase.com에 접속해 오른쪽 위 Sign in을 누릅니다. 깃허브 계정으로 들어가면 편합니다.

  2. 새 프로젝트를 만듭니다

    대시보드에서 New project를 누르고 아래처럼 채웁니다.

    • Name — work-report
    • Database Password — Generate a password를 눌러 만든 뒤 어딘가에 적어 두세요. 다시 볼 수 없습니다.
    • Region — Northeast Asia (Seoul)

    Create new project를 누르면 1~2분쯤 준비 시간이 걸립니다.

  3. 표를 만듭니다

    왼쪽 메뉴에서 SQL Editor를 열고 New query를 누릅니다. 저장소의 work-report/schema.sql 파일을 열어 전체를 복사해 붙여넣고 오른쪽 아래 Run을 누릅니다.

    확인 왼쪽 Table Editor에 표 여섯 개가 보이면 됩니다 — tasks, daily_logs, weekly_items, series_progress, reports, settings

  4. 열쇠 세 개를 복사해 둡니다

    왼쪽 아래 Project Settings → API로 갑니다. (최신 화면에서는 API Keys라는 이름일 수 있습니다.) 아래 세 가지를 메모장 같은 곳에 모아 두세요. 3단계에서 씁니다.

    • Project URL — https://…supabase.co
    • anon public 키 — 새 화면에서는 publishable이라고 적혀 있습니다
    • service_role 키 — 새 화면에서는 secret입니다
    주의 service_role 키는 절대 남에게 보여 주지 마세요. 이 키 하나로 모든 데이터를 읽고 쓸 수 있습니다. Vercel 환경변수에만 넣습니다.

  5. 내 계정을 만듭니다

    왼쪽 Authentication → Users → Add user → Create new user를 고릅니다. 이메일과 비밀번호를 넣고, Auto Confirm User를 꼭 켜 주세요. 이걸 켜지 않으면 확인 메일을 거쳐야 로그인이 됩니다.

  6. 다른 사람이 가입하지 못하게 막습니다

    Authentication → Sign In / Providers에서 Email을 열고 Allow new users to sign up을 끕니다. 혼자 쓰는 앱이니 이제 새 가입은 필요 없습니다.

2단계

구글 드라이브 준비

약 15분

앱이 보고서를 드라이브에 저장하려면, 앱 몫의 구글 계정이 하나 필요합니다. 이걸 서비스 계정이라고 합니다. 사람이 로그인하는 계정이 아니라 프로그램이 쓰는 계정입니다.

  1. 보고서를 담을 폴더를 만듭니다

    drive.google.com에서 폴더를 하나 만듭니다. 이름은 업무보고서 정도면 됩니다. 그 폴더를 열고 주소창을 보면 이렇게 생겼습니다. 

    https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUvWxYz

    folders/ 뒤의 긴 문자열이 폴더 ID입니다. 복사해 두세요.

  2. 구글 클라우드에 프로젝트를 만듭니다

    console.cloud.google.com에 들어가 맨 위 프로젝트 선택기를 누르고 새 프로젝트를 만듭니다. 이름은 work-report로 하겠습니다. 만든 뒤 그 프로젝트가 선택돼 있는지 확인하세요.

  3. 드라이브 API를 켭니다

    왼쪽 메뉴 API 및 서비스 → 라이브러리에서 Google Drive API를 검색해 누르고 사용 버튼을 누릅니다.

    주의 이걸 켜지 않으면 나중에 업로드할 때 API가 사용 설정되지 않았다는 오류가 납니다.

  4. 서비스 계정을 만듭니다

    API 및 서비스 → 사용자 인증 정보로 가서 위쪽 + 사용자 인증 정보 만들기 → 서비스 계정을 고릅니다.

    • 서비스 계정 이름 — work-report
    • 만들고 계속하기를 누른 뒤, 역할(Role)은 비워 둔 채 완료를 누릅니다

    목록에 work-report@….iam.gserviceaccount.com 같은 주소가 생깁니다. 이게 앱의 계정입니다.

  5. 열쇠 파일을 내려받습니다

    방금 만든 서비스 계정을 누르고 키 탭으로 갑니다. 키 추가 → 새 키 만들기 → JSON → 만들기를 누르면 파일이 하나 내려받아집니다.

    주의 이 파일은 비밀번호와 같습니다. 다시 받을 수 없으니 안전한 곳에 두시고, 메신저나 메일로 보내지 마세요.

  6. 파일에서 값 두 개를 꺼냅니다

    내려받은 JSON 파일을 메모장으로 열면 이런 줄들이 있습니다.

    "client_email": "work-report@work-report.iam.gserviceaccount.com",
"private_key": "-----BEGIN PRIVATE KEY-----\nMIIE…\n-----END PRIVATE KEY-----\n",

    두 값을 복사해 둡니다. 복사할 때는 바깥쪽 큰따옴표는 빼고, 안쪽 내용만 가져오세요. private_key는 아주 길고 중간에 \n이 잔뜩 들어 있는데, 그대로 두시면 됩니다. 고치지 마세요.

  7. 폴더를 서비스 계정에 공유합니다

    드라이브로 돌아가 1번에서 만든 폴더에 마우스 오른쪽 → 공유를 누릅니다. client_email 주소를 붙여넣고 권한을 편집자로 바꾼 뒤, 알림 보내기 체크를 풀고 공유를 누릅니다.

    가장 자주 막히는 곳 이 걸음을 빠뜨리면 저장이 실패합니다. 서비스 계정은 자기 저장 공간이 없어서, 사람이 폴더를 빌려줘야만 그 안에 파일을 만들 수 있습니다. 나중에 File not found 오류가 나면 십중팔구 여기입니다.
3단계

Vercel에 앱 올리기

약 10분

앞에서 모은 값들을 넣고 앱을 인터넷에 띄웁니다. 이것도 무료 요금제로 됩니다.

  1. 저장소를 불러옵니다

    vercel.com에 깃허브 계정으로 로그인하고 Add New → Project를 누릅니다. 목록에서 khs386/voting-app을 찾아 Import를 누릅니다.

  2. 시작 폴더를 지정합니다

    설정 화면의 Root Directory 옆 Edit를 누르고 work-report 폴더를 고릅니다.

    놓치기 쉬움 이 저장소에는 앱이 여러 개 들어 있습니다. 여기를 work-report로 바꾸지 않으면 엉뚱한 앱이 배포되거나 빌드가 실패합니다.

  3. 환경변수 일곱 개를 넣습니다

    같은 화면의 Environment Variables를 펼치고 아래 환경변수 표대로 이름과 값을 하나씩 추가합니다. CRON_SECRET은 정해진 값이 없으니, 아무 긴 문자열이나 직접 만들어 넣으시면 됩니다.

    주의 이름은 한 글자도 틀리면 안 됩니다. 대소문자와 밑줄까지 그대로 복사해 넣으세요. NEXT_PUBLIC_으로 시작하는 것들이 특히 헷갈립니다.

  4. 배포합니다

    Deploy를 누르고 기다립니다. 1~2분이면 끝납니다. 끝나면 …vercel.app 주소가 나옵니다. 이게 앱 주소입니다.

    확인 그 주소로 들어가 로그인 화면이 뜨면 성공입니다.

첫 보고서 만들어 보기

약 10분

제대로 연결됐는지 실제로 한 바퀴 돌려 봅니다. 순서대로 하시면 됩니다.

  1. 로그인합니다

    1단계 5번에서 만든 이메일과 비밀번호로 들어갑니다.

  2. 시리즈 진행률을 넣습니다

    위쪽 시리즈를 누르고 세 칸에 숫자를 넣은 뒤 저장합니다. 노션 화면에 보이는 값을 그대로 옮겨 적으시면 됩니다. 아래 막대가 바로 바뀌면 잘 들어간 것입니다.

  3. 업무를 두어 개 등록합니다

    업무에서 업무명, 진행 상태, 진행률, 마감을 넣고 추가합니다. 진행률과 마감은 비워 둬도 됩니다. 비우면 보고서에서 그 부분이 빠집니다.

  4. 오늘 한 일을 적습니다

    일일 기록에서 오늘 날짜를 확인하고, 업무 목록에서 고르기로 업무를 넣습니다. 세부내용 칸에 한 줄에 하나씩 적고 저장을 누릅니다. 여기서 저장하면 업무 목록의 상태와 진행률도 같이 갱신됩니다.

  5. 보고서를 만듭니다

    보고서에서 보고서 만들기를 누릅니다. 아래 미리보기에 보고서가 나타납니다.

  6. 드라이브에 저장해 봅니다

    구글 드라이브에 저장을 누릅니다. 초록 줄에 파일 이름과 드라이브에서 열기 링크가 뜨면 성공입니다.

    확인 2단계에서 만든 드라이브 폴더에 report_2026-09-04.html 같은 파일이 생겼는지 직접 열어 보세요. 한글이 제대로 보이면 끝입니다.
    막히면 빨간 줄에 오류가 뜨면 그 문장을 아래 문제 해결에서 찾아보세요.
5단계

자동 생성 켜기

약 5분

여기까지 하면 손으로는 다 됩니다. 이제 정해진 시각에 알아서 만들게 합니다. 평일 저녁 6시에 일일 보고서, 금요일 오후 5시에 주간 보고서입니다. 주말과 공휴일은 알아서 건너뜁니다.

  1. 이미 설정돼 있습니다

    시각은 저장소의 vercel.json에 들어 있어서, 배포하면 자동으로 등록됩니다. 따로 하실 일은 없습니다. Vercel의 Settings → Cron Jobs에서 등록됐는지 볼 수 있습니다.

  2. 무료 요금제로 둘 다 돌아갑니다

    Vercel 무료(Hobby) 요금제의 제한은 자동 실행 하나가 하루에 한 번까지입니다. 일일은 하루 한 번, 주간은 주 한 번이라 둘 다 무료로 동작합니다. 따로 하실 일은 없습니다.

    알아 둘 것 무료 요금제에서는 지정한 시(hour) 안의 아무 때나 실행됩니다. 18시 정각이 아니라 18시 40분에 만들어질 수 있다는 뜻입니다. 분 단위로 정확해야 한다면 깃허브 액션에서 앱 주소를 불러 주는 방법을 쓰면 됩니다.

    자동으로 안 만들어진 날이 있어도 괜찮습니다. 보고서 화면에서 보고서 만들기를 누르면 그만입니다.

  3. 잘 도는지 한 번 확인합니다

    기다리지 않고 지금 시험해 보려면, 터미널에서 아래를 실행합니다. 여기에_CRON_SECRET과 주소는 본인 것으로 바꾸세요. 

    curl -H "Authorization: Bearer 여기에_CRON_SECRET" \
  "https://내앱.vercel.app/api/cron/daily?date=2026-09-04&force=1"

    {"ok":true,…}가 돌아오고 드라이브에 파일이 생기면 정상입니다. force=1은 주말·공휴일 검사를 건너뛰라는 뜻이라 아무 날에나 시험할 수 있습니다.

참고

환경변수 표

Vercel의 Environment Variables에 넣을 값들입니다. 일곱 개 모두 필요합니다.

이름값어디서 가져오나
NEXT_PUBLIC_SUPABASE_URL https://…supabase.co 1단계 4번 · Project URL
NEXT_PUBLIC_SUPABASE_ANON_KEY eyJ… 로 시작하는 긴 문자열 1단계 4번 · anon public (publishable)
SUPABASE_SERVICE_ROLE_KEY eyJ… 로 시작하는 긴 문자열 1단계 4번 · service_role (secret)
GOOGLE_SERVICE_ACCOUNT_EMAIL …iam.gserviceaccount.com 2단계 6번 · JSON의 client_email
GOOGLE_PRIVATE_KEY -----BEGIN PRIVATE KEY----- 로 시작하는 아주 긴 값 2단계 6번 · JSON의 private_key (따옴표 빼고)
GOOGLE_DRIVE_FOLDER_ID 1AbCdEf… 같은 문자열 2단계 1번 · 폴더 주소의 folders/ 뒤
CRON_SECRET 아무 긴 임의 문자열 직접 만들기 (예: 비밀번호 생성기)
기억할 것 환경변수를 고친 뒤에는 반드시 다시 배포해야 반영됩니다. Vercel의 Deployments에서 맨 위 항목의 ⋯ → Redeploy를 누르세요.

문제 해결

화면에 뜬 문장을 찾아보세요.

구글 드라이브 환경변수가 설정되지 않았습니다

드라이브 관련 환경변수 셋 중 하나가 빠졌습니다. GOOGLE_SERVICE_ACCOUNT_EMAIL, GOOGLE_PRIVATE_KEY, GOOGLE_DRIVE_FOLDER_ID가 모두 있는지 Vercel에서 확인하고 다시 배포하세요.

드라이브 업로드 실패: File not found: 1AbC…

폴더를 서비스 계정에 공유하지 않았습니다. 2단계 7번으로 돌아가, 드라이브 폴더를 client_email 주소에 편집자로 공유하세요. 폴더 ID를 잘못 복사한 경우도 같은 오류가 납니다.

구글 토큰 발급 실패: invalid_grant

GOOGLE_PRIVATE_KEY 값이 깨졌습니다. JSON 파일에서 다시 복사하되, 바깥 큰따옴표는 빼고 안쪽만 가져오세요. 중간의 \n은 지우거나 바꾸지 말고 그대로 둡니다.

Google Drive API has not been used in project …

2단계 3번을 건너뛰었습니다. 구글 클라우드에서 Google Drive API를 사용으로 켜 주세요. 켠 뒤 몇 분 기다려야 할 수 있습니다.

로그인이 안 되고 "Invalid login credentials"가 뜹니다

계정을 만들 때 Auto Confirm User를 켜지 않았을 수 있습니다. Supabase의 Authentication → Users에서 해당 사용자를 지우고 다시 만들면서 그 항목을 켜세요.

화면은 뜨는데 업무 목록이 계속 비어 있습니다

Supabase 주소나 키가 잘못됐을 가능성이 큽니다. NEXT_PUBLIC_SUPABASE_URL과 NEXT_PUBLIC_SUPABASE_ANON_KEY의 철자를 확인하고 다시 배포하세요. 표를 만드는 SQL을 실행하지 않은 경우도 같습니다.

자동 실행 주소를 불렀더니 "CRON_SECRET이 설정되지 않았습니다"

안전을 위해 비밀값 없이는 동작하지 않게 해 두었습니다. Vercel에 CRON_SECRET을 넣고 다시 배포하세요. "권한 없음"이 뜬다면 넣은 값과 부른 값이 서로 다른 것입니다.

배포가 실패합니다 / 엉뚱한 화면이 뜹니다

Root Directory가 work-report가 아닙니다. Vercel의 Settings → General → Root Directory를 고치고 다시 배포하세요.

드라이브에 저장된 파일을 열었더니 한글이 깨져 보입니다

최신 코드에서 고쳐 둔 부분입니다. Vercel이 예전 코드로 배포돼 있을 수 있으니 Deployments에서 가장 최근 커밋으로 다시 배포하세요.

막히는 곳이 있으면 화면에 뜬 문장을 그대로 알려 주세요. 어느 걸음에서 어긋났는지 짚어 드리겠습니다. · 체크 표시는 이 브라우저에만 저장됩니다.
